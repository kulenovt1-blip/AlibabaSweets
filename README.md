# Али-Баба · Заявки (PWA) — инструкция

Версия 29 (сервер Code.gs — 27). Приложение для торговых представителей: каталог, заявка в WhatsApp, история, магазины и визиты. Данные хранятся в Google Таблице, сервер — Google Apps Script.

## Файлы
| Файл | Назначение |
|---|---|
| `index.html`, `styles.css`, `app.js`, `manifest.webmanifest`, `logo.jpg`, иконки, `img/` | сайт (PWA) — выкладывается на хостинг |
| `sw.js` | Service Worker: работа без интернета |
| `Code.gs` | серверная часть — вставляется в Apps Script таблицы (на хостинг не нужен) |
| `tests/` | локальные проверки (на хостинг не нужны) |

Ссылка на прайс и ссылка на веб-приложение Apps Script вписаны в `app.js` (`SHEET_CSV`, `API_URL`). **Ключей и паролей в файлах нет** и быть не должно: доступ к базе — по личному входу.

## Шаг 1. Выложить сайт
1. Откройте netlify.com/drop и перетащите **всю папку** (папку `tests` и файл `Code.gs` можно не выкладывать).
2. Откройте полученную ссылку `https://...netlify.app`. Страницу с компьютера двойным кликом открывать нельзя — прайс не загрузится.
3. Обновляете сайт — заменяйте **все** файлы сразу и обновляйте страницу дважды.

## Шаг 2. Прайс (Google Таблица)
Лист с колонками, первая строка — заголовки:
`Категория | Название | Граммовка | Цена (без НДС) | Цена (с НДС) | Единица (шт/кг/кор) | Фото`

Необязательная колонка «Продвигать» (с версии 31; старое название «Ходовой» тоже понимается): «да» — товар во вкладке «Продвигать» с меткой «Продвигаем».
Колонки ищутся по заголовкам, порядок не важен. **Без колонки «Цена (с НДС)» режим «С НДС» работать не будет.** Если колонка просто «Цена», она считается ценой без НДС. Колонка «Ходовой» (значение «да») — товары попадут в раздел «Ходовые».
1. Файл → Поделиться → Опубликовать в интернете → выберите **только лист с прайсом** и формат **CSV** → Опубликовать.
2. Ссылку вставьте в `app.js` в `SHEET_CSV`.
3. Изменили цены → в приложении «Настройки» → «Обновить прайс» (Google обновляет публикацию за несколько минут).

**Публиковать в интернет можно только лист с прайсом.** Остальные листы содержат заявки и учётные записи.

### Фото товаров (колонка «Фото»)
**Способ А (рекомендуется, работает офлайн):** положите фото в папку `img/`, а в колонке «Фото» впишите только имя файла, например `finiki-caramel.jpg`. Советы: квадратные снимки, jpg или webp, 600×600 px, до 150 КБ; имя латиницей без пробелов.
**Способ B:** ссылка на файл в Google Drive с доступом «все, у кого есть ссылка» или прямая ссылка на картинку. Такие фото не сохраняются для работы без интернета.

## Шаг 3. Сервер (Apps Script)
1. Откройте **ту же таблицу** → Расширения → Apps Script.
2. Удалите весь код в окне, вставьте содержимое `Code.gs`. Нажмите 💾.
3. **Развернуть → Новое развёртывание** → тип **Веб-приложение**: выполнять от имени **Я**, доступ — **Все**. Разрешите доступ.
4. Скопируйте **URL веб-приложения** (заканчивается на `/exec`) и вставьте в `app.js`: `API_URL: '...'`.
5. Если меняете код позже: Развернуть → Управление развёртываниями → ✏️ → Версия: **Новая версия** → Развернуть (ссылка не меняется). Новое развёртывание с другой ссылкой не подходит.

Листы **Торговые**, **Магазины**, **Заявки**, **Визиты**, **Получатели** создаются сами.

«Доступ: Все» у веб-приложения означает только то, что адрес скрипта открыт для запросов. Данные скрипт отдаёт лишь тем, кто вошёл по паролю: каждый запрос несёт токен, подписанный сервером.

## Шаг 4. Учётные записи и роли

### Как это устроено
- Профили — строки листа **Торговые** (колонка «Имя»). Там же: «Роль» (`admin` или пусто = торговый), версия доступа, **хеш** пароля, **хеш** приглашения. Колонки B–H этого листа скрипт занимает сам: **до обновления они должны быть пустыми**, включая строку заголовков. Если там есть свои записи, перенесите их на другой лист — иначе скрипт остановится с сообщением «колонка занята».
- Пароль задаёт сам торговый по **одноразовому приглашению** (код вида `XXXX-XXXX-XXXX-XXXX`, действует 48 часов, привязан к профилю). Открытой регистрации, почты и SMS нет.
- Ни пароли, ни приглашения в открытом виде нигде не хранятся и в журнал не пишутся. Администратор пароль не видит и узнать не может — только выдать новое приглашение.
- Вход: имя профиля и пароль. Список профилей до входа не показывается.
- После 5 неудачных попыток вход для этого имени закрывается на 15 минут (после 60 неудач за 10 минут — для всех на 5 минут). Ответ сервера не говорит, существует ли профиль.
- Вход действует 14 дней, потом приложение попросит пароль снова. Неотправленные заявки и отметки при этом не теряются.

### Первый администратор (делает владелец таблицы, один раз)
Первого администратора нельзя назначить из приложения — только из самой таблицы. Это сделано намеренно: право редактировать таблицу есть только у владельца.

1. Откройте таблицу и обновите страницу. Появится меню **Али-Баба**.
2. **Али-Баба → Доступ: назначить администратора и выдать приглашение.** Впишите имя профиля (если его нет на листе «Торговые», он будет добавлен). Google один раз попросит разрешения для скрипта.
3. Появится окно с **одноразовым приглашением**. Запишите код: он показывается один раз.
4. Откройте приложение (версии 27) → **«У меня есть приглашение»** → имя профиля, код, новый пароль дважды. Вы вошли как администратор.
5. **Проверьте вход по паролю:** «Настройки» → «Профиль» → «Выйти из профиля» → войдите снова по имени и паролю.
6. В приложении: «Настройки» → «Профиль» → **«Доступ и профили»** → для каждого торгового нажмите «Приглашение» и передайте ему код лично.
7. Когда все перешли на вход по паролю: **Али-Баба → Доступ: включить обязательную авторизацию.** Меню не даст это сделать, пока нет администратора, который уже входил по паролю (шаг 5).

Что меняет шаг 7. Приложение версии 27 работает только по паролю с первого дня. «Обязательная авторизация» отключает запасной вход для устройств со старой версией приложения (см. «Переход с версии 26»). Если ключ для старых устройств вы не задавали, шаг 7 ничего не меняет в работе, но его всё равно стоит выполнить.

### Приглашение, сброс пароля, отзыв доступа
- **Новый торговый:** «Доступ и профили» → «Новый профиль» → «Приглашение».
- **Забыл пароль:** «Сбросить пароль». Старый пароль и все входы этого профиля сразу перестают действовать; торговый задаёт новый пароль по приглашению.
- **Уволился или потерял телефон:** «Отозвать доступ». Вернуть доступ можно новым приглашением.
- **Сменить роль:** «Сделать администратором» / «Сделать торговым». Профилю придётся войти заново. Единственного действующего администратора разжаловать или отозвать нельзя.
- Администратор может удалить профиль (кроме своего): строка исчезает с листа «Торговые», войти под ним больше нельзя, а его заявки и визиты остаются в таблице под прежним именем. Если позже завести профиль с тем же именем, эти заявки будут считаться его. Если человек не работает временно — отзывайте доступ, а не удаляйте. Отозванному профилю роль не меняют: сначала выдайте приглашение. Не переименовывайте профиль на листе вручную — его заявки станут «чужими».
- Единственному действующему администратору сбросить пароль из приложения нельзя (ни себе, ни через другого торгового). Если администратор один и забыл пароль: меню таблицы **Али-Баба → Доступ: выдать приглашение профилю**.

### Кто что может
| Действие | Администратор | Торговый |
|---|---|---|
| Каталог, магазины, получатели, история всех заявок, лента магазина — просмотр | да | да |
| Создать заявку (от своего имени) | да | да |
| Изменить (24 ч), удалить, вернуть (24 ч) **свою** заявку | да | да |
| Изменить **любую** заявку с торговым, без срока (владелец остаётся прежним) | да | нет |
| Изменить, удалить, вернуть **чужую** заявку | нет | нет |
| Изменить заявку без торгового | нет (только назначить владельца) | нет |
| Магазины: добавить, изменить, удалить; статус, контакт, план, вопрос | да | да |
| Визит: отметить; изменить, отменить, восстановить **свой** | да | да |
| Профили: список, добавить, приглашение, сброс пароля, отзыв, роль | да | нет |
| Назначить владельца заявкам без торгового | да | нет |

Права проверяет сервер при каждом запросе. Спрятанная кнопка — только удобство.

### Заявки без торгового
В старых версиях могли появиться заявки без владельца. Они видны в «Истории» → «Все заявки» с пометкой «без торгового», их можно открыть и повторить. Изменить, удалить или вернуть их нельзя, пока у них нет владельца.

Назначить владельца: «Доступ и профили» → «Заявки без торгового».
1. **Сделайте копию таблицы** (Файл → Создать копию).
2. «Пробный прогон» — ничего не меняет, показывает число заявок и список.
3. Выберите торгового, отметьте «Я проверил список», подтвердите.
4. Сервер сам сделает копию листа «Заявки» (лист «Заявки (копия …)») и только потом запишет владельца в колонку «Торговый» и в данные заявки.

Все найденные заявки получают одного владельца. Если их нужно разделить между несколькими торговыми, впишите имена в колонку «Торговый» вручную для части строк, а остальным назначьте владельца инструментом.

### О надёжности паролей — честно
В Apps Script нет Argon2id, scrypt и bcrypt. Используется **PBKDF2-HMAC-SHA256** с солью, числом итераций и серверным «перцем» (секрет в свойствах скрипта, не в таблице). Это настоящая функция для паролей, но слабее Argon2id, а число итераций ограничено скоростью Apps Script (по умолчанию 4000 — намного меньше, чем рекомендуют для PBKDF2).

Что из этого следует:
- Пока таблица не утекла вместе со свойствами скрипта, подобрать пароли по хешам нельзя: без «перца» хеши бесполезны.
- Если утекло и то и другое, **короткие и простые пароли подберут быстро**. Поэтому пароль — не меньше 8 знаков, лучше фраза из нескольких слов (чем длиннее, тем надёжнее: 8 знаков — нижняя граница, а не рекомендация).
- **Али-Баба → Доступ: замер скорости хеширования** покажет, сколько итераций сервер выдерживает; число меняется в «Доступ: число итераций». Действующие пароли продолжат работать, их хеши обновятся при следующем входе.
- Доступ на редактирование таблицы давайте только тем, кому доверяете как администратору: такой человек может сам назначить себя администратором.
- Секреты `TOKEN_KEY` и `PEPPER` лежат в Apps Script → Настройки проекта → Свойства скрипта. Не удаляйте их: без `PEPPER` все пароли придётся задавать заново, без `TOKEN_KEY` всем придётся войти заново.

## Версия 27: как обновить (переход с версии 26)
Порядок важен. Между шагами 3 и 6 приложение у торговых работать с базой не будет — выберите спокойное время и предупредите их.

1. **Сделайте копию таблицы** (Файл → Создать копию).
2. Попросите торговых открыть приложение при интернете и дождаться строки «Синхронизировано». Неотправленное не пропадёт и при обновлении, но так проще.
3. Apps Script → вставьте новый `Code.gs` целиком → 💾 → Развернуть → Управление развёртываниями → ✏️ → **Новая версия** → Развернуть.
4. Обновите страницу таблицы. Выполните шаги 1–3 раздела «Первый администратор».
5. Выложите на хостинг ВСЕ файлы сайта (`index.html`, `styles.css`, `app.js`, `sw.js`, …).
6. Откройте приложение, обновите страницу дважды. «Настройки» → «Служебная информация»: Версия 27, Code.gs: 27. Выполните шаги 4–7 раздела «Первый администратор».

Что увидит торговый: экран «Вход». Он выбирает «У меня есть приглашение», вводит своё имя, код и новый пароль. Заявки и отметки, которые не успели уйти со старой версией, отправятся после входа **под тем же профилем**.

**Необязательно — ключ для старых устройств.** Если какое-то устройство надолго останется на версии 26, оно сможет дослать накопленные заявки, только если на время перехода задать прежний ключ: **Али-Баба → Доступ: ключ для устройств со старой версией**. Читать базу такое устройство уже не сможет. После «включить обязательную авторизацию» ключ перестаёт действовать. Прежний ключ был в открытом коде — считайте его известным посторонним и не держите этот режим дольше необходимого.

**Старый ключ из версии 26 больше нигде не нужен.** В файлах его нет.

## Версия 35: одноимённые магазины, заметки, маршрут на день, история по периодам
Включает всю версию 34 (её отдельно выпускать не нужно; ветка `v34` на GitHub — на случай, если понадобится). Меняются сайт (index.html, styles.css, app.js, sw.js) и `Code.gs` (35). Сначала `Code.gs`, потом сайт. Перед выпуском на листе «Магазины» **колонка AB** должна быть пустой (там будут заметки), иначе сервер остановится с понятной ошибкой. Новый лист «Маршрут дня» сервер создаёт сам. Проверка — `docs/RELEASE.md`, «Проверка v35».

**Магазины с одинаковыми названиями.** Несколько «Продуктов» в одном городе больше не склеиваются в таблице: магазин определяется по своему номеру (ID). При добавлении приложение спросит: «Уже есть «Продукты» · ул. Абая 1. Это тот же магазин?»; новый одноимённый — только с адресом, по нему их различают. В истории у таких магазинов виден адрес. Если при записи места точки рядом (до 30 м) уже записана другая точка — вопрос, не дубль ли это.

**Заметки о точке.** В карточке магазина раздел «Заметки» — постоянный текст (как подъехать, кого спросить, когда принимают товар), видно всем, хранится в колонке AB.

**Маршрут на день — общий.** «В маршрут на сегодня» и «Не сегодня» теперь хранятся в таблице (лист «Маршрут дня»), а не только на телефоне. Администратор в «Маршрут» → «Маршрут торгового на день» выбирает торгового и день, добавляет и убирает точки — у торгового они появятся в «На сегодня» после синхронизации. Правки дня, сделанные на телефоне до обновления, один раз переносятся в таблицу.

**История по периодам** — см. раздел «История» ниже. **Фильтр по статусу** в «Все магазины» (в том числе «Без статуса»).

## Версия 34: история с сервера, защита правок, дата поставки задним числом
Меняются сайт (index.html, styles.css, app.js, sw.js) и `Code.gs` (34). Сначала `Code.gs` (новая версия развёртывания), потом сайт — иначе приложение 34 не будет отправлять заявки на сервер 33 («Обновите Code.gs»). Колонок не добавляется. Проверка — `docs/RELEASE.md`, «Проверка v34».

**История.** Показывается версия заявки с сервера; копия на телефоне — только пока заявка не отправлена. Если заявку, пока вы её правили, изменил кто-то другой, правка не затрёт его изменения: приложение скажет «Заявку уже изменили (кто, когда). Откройте её заново», а ваша правка останется в черновиках.

**Администратор** удаляет и возвращает любую заявку с торговым (вернуть можно в течение 24 ч). Кто удалил — видно в колонке M «Удалена» листа «Заявки» («2026-10-15 23:10 · Имя») и в ленте магазина.

**Дата поставки.** Сама — ближайшая пятница после времени заявки. Если заявку приняли раньше, укажите «Время заявки» (сразу под датой поставки) — поставка пересчитается. Вручную — любая дата до 60 дней назад, но не раньше дня заявки. Правка заявки дату поставки не меняет.

**Мелочи.** «Заказать снова» (было «Повторить») спрашивает, если корзина не пуста. «Заявка» из карточки другого магазина спрашивает про перенос товаров; «Отменить» рядом со «Сменить» возвращает прежний магазин. «Все магазины»: вкладки «Брали заявку» (за 5 дней), «Давно без визита» (ни визита, ни заявки — заявка тоже считается посещением) и «Не работаем», фильтр по району; район ищется в поиске. При вводе адреса подсказываются улицы, уже записанные в этом городе. Сохранения в карточке магазина подтверждаются сообщением и пометкой у раздела. «Служебная информация» помнит последнюю ошибку синхронизации.

## Версия 33: новый вид, маршрут «Еду сюда», юрлицо

Режим цен «с НДС / без НДС» — вверху справа. «Оформить» — в полосе внизу. В «Истории» сверху «Итоги», ниже выбор дня и заявки; удалённые — строкой «Недавно удалённые» внизу (вернуть можно 24 ч). В «Профиле» — кто вошёл и что сделано сегодня, черновики, настройки, тема и размер текста, «Выйти».

## Маршрут, ответственный, место точки (с версии 31)
- Дни маршрута хранятся у точки в таблице («Магазины», колонка S, например `Пн, Чт`) и общие для всех торговых. Их можно править в приложении или прямо в таблице.
- «Ответственный» (колонка T) необязателен. Пусто — точка в эти дни в маршруте у всех. В карточке «Беру точку» — точка только у вас; «Освободить точку» — снова общая. Чужую точку передаёт администратор. Имя — как на листе «Торговые».
- «Цены для магазина» (колонка U): `с НДС`, `без НДС` или пусто (тогда норма — по последней заявке в точку). При расхождении приложение спрашивает при отправке.
- Место точки (колонки V–Z): кнопка «Записать место» в карточке — телефон спросит разрешение на местоположение. «Как проехать» открывает карты с этой точкой. Удалить записанное место может только администратор (кнопка «Удалить место», с версии 32).
- «Пройдено»: точки маршрута, где сегодня был закрывающий визит или заявка. С версии 32 туда же попадают ваши заявки и визиты в точки не из маршрута — с пометкой «вне маршрута»; в счёт «из N» они не входят.

## Каталог: «Брал раньше», «Ходовые», «Продвигать» (с версии 31)
- «Брал раньше» — когда выбран магазин: что точка заказывала в последних 5 заявках (не старше полугода) и сколько в прошлый раз.
- «Ходовые» считаются сами: 15 товаров, которые чаще всего встречались в заявках за 60 дней (от 3 заявок). Числа — в начале `Code.gs` (`HOT_DAYS`, `HOT_TOP`, `HOT_MIN`).
- «Продвигать» — решение фирмы: администратор отмечает товары в «Профиль → Продвигать товары» (хранится на листе «Продвигать») или словом «да» в колонке прайса «Продвигать» (старое название «Ходовой» тоже понимается). Вкладка видна, только если отмечен хотя бы один товар.
- Товар узнаётся по названию, граммовке и единице: если переименовать товар в прайсе, отметка «Продвигать» с него слетит (администратор увидит её в разделе «Нет в прайсе»).

## Итоги и статус «Отказались» (с версии 31)
- «История» → сверху «Итоги»: неделя (с понедельника), месяц, год и прошлый такой же период целиком. Торговый видит свои заявки, администратор — всех с разбивкой. Удалённые заявки не считаются.
- Статус «Отказались» — причина по желанию; частые причины появляются кнопками (со второго использования). Такие точки снова предлагаются в «Стоит заехать» через 3 месяца.

## Разделы приложения (с версии 29)
Внизу экрана четыре раздела: **Маршрут** (стартовый: точки на сегодня, у каждой — «Визит» и «Заявка»), **Заявка** (каталог и корзина), **История**, **Профиль** (до v33 — «Ещё») (профиль, черновики, настройки, администрирование). Разделы открываются на весь экран, вернуться — кнопкой «Назад» сверху или «назад» телефона. Постоянный маршрут по дням недели и правила подсказок — «Маршрут» → «Маршрут по дням недели».

## Маршрут: отложенные точки (с версии 30)
Результаты визита «Никого не было» и «Зайти позже» откладывают точку: она остаётся в маршруте на сегодня, внизу списка, с пометкой «Отложено в …». Зайти ещё раз — «Визит» или «Заявка»; не заходить сегодня — «Не зайду» (с возможностью отменить). Если у точки не было плана, приложение ставит план на сегодня: если до конца дня точку так и не закрыли, завтра она будет в «Стоит заехать» как просроченная. Визит с другим результатом или заявка сегодня план снимают.

## Вид: тема, размер текста, каталог
«Профиль» → «Настройки» → «Вид». Тема: светлая (по умолчанию), тёмная или «как в телефоне». Размер текста: обычный, крупный, очень крупный. Каталог товаров: плиткой (по умолчанию, два товара в ряд, крупное фото) или списком (товар — строка, кнопки крупнее). Каталог переключается и кнопкой «Список» / «Плитка» рядом с поиском. Всё меняется сразу, без кнопки «Сохранить», и только на этом телефоне — на других устройствах торговых ничего не меняется. Светлая тема выбрана по умолчанию сознательно: на улице днём тёмная читается хуже.

## Цены с НДС и без НДС (с версии 30)
Переключатель «С НДС / Без НДС» — вверху экрана «Заявка», как раньше; им можно показать клиенту обе цены. На оформлении заявки режим написан крупно, рядом кнопка «Переключить на …».
Приложение знает, какой режим обычен для точки: по умолчанию — режим последней заявки в эту точку (из заявок, которые есть на этом телефоне). В карточке магазина, раздел «Цены для магазина», можно выбрать явно: «С НДС», «Без НДС» или «По последней заявке». Этот выбор пока хранится только на телефоне (переносится резервной копией); в таблицу — в следующей версии.
При отправке приложение один раз спрашивает, если режим заявки не совпадает с обычным для точки или режим переключали, пока в корзине были товары (если переключили и вернули обратно — не спрашивает). Кнопки: «Отправить <как есть>» и «Переключить на <другой режим>». Ручные цены при переключении сбрасываются — об этом сказано в том же вопросе. Текст заявки для оператора не изменился.

## История: вкладки «Мои» и «Все заявки», итоги за период (с версии 35)
- «Мои» — заявки вашего профиля. «Все заявки» — заявки всех торговых, у чужих указано имя; администратор может выбрать одного торгового.
- Чужую заявку торговый может открыть и «Заказать снова», но изменить или удалить нельзя (администратор — может, с версии 34): сервер проверяет права по входу.
- Сверху выбор периода: **День · Неделя · Месяц · Год**, стрелки ‹ › листают, нажатие на дату открывает календарь, «К этой неделе» (и т. п.) возвращает к текущему. Неделя — с понедельника, месяц и год — с первого числа.
- Под ним тёмная плашка «Итоги» за этот же период и прошлый такой же (торговый — свои, администратор — все с разбивкой по торговым или выбранного). Ниже — заявки этого периода: неделя и месяц — по дням, год — по месяцам (нажатие открывает месяц). Итоги и список считаются по одним и тем же заявкам, поэтому числа сходятся.
- Сразу загружены заявки всех торговых за 7 дней и свои за 30 дней; более старый период запрашивается у сервера при выборе.

## Удаление и возврат заявок
- Удалённая заявка попадает в «Недавно удалённые», вернуть её можно в течение 24 часов. Срок проверяет сервер.
- Если вы нажали «Вернуть» или отправили правку вовремя, но интернета не было, сервер учтёт время нажатия. Ждать отправки такая операция может не дольше 7 дней. Если срок вышел, приложение сообщит об этом: заявка останется удалённой, а непринятая правка попадёт в черновики.
- Время нажатия сообщает устройство, и сервер не может его проверить. Поэтому сроки 24 часа — защита от случайностей, а не от намеренной подделки: торговый, изменивший приложение, может вернуть или исправить **свою** заявку в пределах 7 дней. Чужую — не может.
- В таблице строка заявки **не стирается**: в колонке «Удалена» ставится дата.

## Сверка старых данных (с версии 26)
Меню таблицы «Али-Баба» → «Сверка: пробный прогон» (ничего не меняет, отчёт на листе «Сверка»), затем, после просмотра, «применить». Перед этим сделайте копию таблицы. Неоднозначные записи остаются как есть. По окончании таблица показывает окно с итогом; если сверка не выполнилась — с текстом ошибки.

То же самое администратор может сделать из приложения: «Профиль» → «Доступ и профили» → «Проверка и исправление данных». Кнопка «Проверить данные» ничего не меняет (даже отчёт не пишет) и показывает и результат сверки, и заявки без торгового; «Исправить» применяет сверку.

## Правка заявки и дата «Заявка сделана»
- Правка сохраняется кнопкой «Сохранить изменение» сразу в таблицу. В WhatsApp правка не отправляется: если оператору нужно знать об изменении, сообщите ему отдельно.
- В корзине есть поле «Заявка сделана» (с версии 30 — раздел «Время заявки» внизу оформления, по умолчанию свёрнут и показывает «сейчас»). Его можно поставить в прошлое, если заявку приняли раньше, а вносите позже, и исправить у существующей заявки. Будущее время не принимается.
- Срок правки для торгового (24 ч) считается от момента, когда заявка записана на сервер (колонка «Время»), а не от даты «Заявка сделана»: сменой даты срок не продлить.

## Лист «Получатели»
Колонки: «Имя», «Телефон», «Города (через запятую; пусто = все)», «По умолчанию (да)». Пример: `Айгуль | 77011234567 | Астана | да`. Список редактируется прямо в таблице.

## Локальные проверки
Нужен Node.js 20+. Сети, настоящей таблицы и рабочего сервера проверки не касаются: таблица и браузер имитируются в памяти.

```
node --test tests/server.test.js tests/client.test.js
```

Что эти проверки **не** покрывают: саму платформу Apps Script и Google Таблицы (скорость хеширования, квоты, поведение настоящих ячеек и блокировок) и внешний вид приложения в браузере. Это проверяется вручную на копии таблицы.

## Если что-то не работает
- **«Требуется вход» вверху экрана** — нажмите и войдите. Неотправленное сохранено и уйдёт после входа.
- **«Неверный профиль или пароль»** — имя нужно вводить так, как оно записано на листе «Торговые». Забыли пароль — попросите администратора о сбросе.
- **«Слишком много неудачных попыток»** — подождите 15 минут.
- **Приглашение «не подошло»** — оно одноразовое, действует 48 часов и привязано к имени профиля. Попросите новое.
- **Нельзя выйти из профиля** — есть неотправленные операции. Подключитесь к интернету и дождитесь «Синхронизировано».
- **«На сервере старая версия Code.gs»** — вставьте актуальный `Code.gs` и сделайте **новую версию** развёртывания.
- **Заявка «не принята сервером» и оказалась в черновиках** — сервер отклонил её (причина указана в сообщении). Откройте черновик, проверьте и отправьте снова.
- **Вход невозможен, хотя пароль верный** — на листе «Торговые» две строки с одним именем. Оставьте одну.
- **Красная плашка «Файлы сайта разных версий»** — загрузите все файлы заново.
- **«Страница открыта как файл (file://)»** — откройте сайт по https-ссылке с хостинга.
- **«Прайс не загружен…»** — ссылка не на CSV или лист не опубликован.
- **Жёлтая плашка «Не заполнена цена…»** — заполните цены у перечисленных товаров.
